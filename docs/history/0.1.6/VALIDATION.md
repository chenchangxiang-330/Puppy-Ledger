# 0.1.6 验证记录

基线为已交付 0.1.5 源码，修改前核对所有生产 Dart 文件均一致。保留应用名、包名、原数据路径、签名配置、三主题素材和原图标；版本递增至 0.1.6+7。数据库 schema 2，备份格式 v2。

## 数据与迁移

| 场景 | 自动化验证 |
| --- | --- |
| 原版数据库升级 | 以真实 schema-1 SQLite 创建旧支出、旧退款和已停用分类，再由新 Store 打开升级 |
| 字段保留 | 对照原 ID、整数分金额、日期、备注、createdAt、updatedAt 逐字段一致 |
| 原分类历史 | 退款另存原分类 ID 和名称，后续编辑、删除撤销、v2 备份恢复仍保留 |
| 100 元支出＋100 元退款 | 收入 10000 分、支出 10000 分、结余 0；支出分类仍为 10000 分 |
| 防止重复迁移 | 关闭重开后的所有账目和分类映射完全相同，不新增重复数据 |
| 迁移中途故障 | 在创建新索引时注入冲突，故障发生于旧表已删除之后；验证 schema、旧记录和 user_version 全部回滚至 1，移除故障后可成功重试 |
| 旧 ID 冲突 | 旧分类占用 income-refund 时保留旧分类并给新退款分类分配其他 ID |
| v1 ZIP 导入 | 与数据库升级生成同样的记录；重复恢复不会累加账目 |
| v2 ZIP 往返 | 收入分类、分工设置及历史字段完整恢复；图片验证、ZIP 校验、事务失败回滚沿用原测试 |
| 收支隔离 | Controller 校验、Store 校验和 SQLite 复合外键约束类别与账目类型一致 |
| 分类停用 | 收入三个默认分类均测试新增、改名、停用、编辑旧记录、删除与精确撤销；同名可存在于不同类型，同类型重名拒绝 |
| 设置独立 | 交换角色、切换主题、重启后账目字段不变；角色和主题分别保存 |
